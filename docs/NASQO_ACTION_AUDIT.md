# تدقيق أزرار وعمليات NASQO Pro Mobile وربطها بـ Odoo 19

التاريخ: 2026-11-15. النطاق: `src/Prototype.tsx` و`src/LiveInvoices.tsx` والواجهة المنشورة على `/nasqo-mobile/`.

## ضمان عدم تغيير التصميم

- لم يتم تعديل `src/prototype.css` أو ملفات `src/mobile/` المحمية أثناء هذا التحديث.
- عدد حقل `input` بقي 33 و`select` بقي 15؛ معرفات `data-testid` بقيت 64 وأسماء `aria-label` النصية بقيت 124 بالمقارنة مع PR #1 الأصلي.
- اختصارات لوحة التحكم التسعة والبطاقات الثماني بأسمائها وترتيبها الأصلي في وضع Odoo.
- عناصر أزرار التصفية الستة جرى تحويلها من JSX متكرر إلى حلقة React بدون حذفها من الواجهة؛ يمكن اختيار الفترة والترتيب.

## طبقة الأمان والتوافق

- كل رابط إلى نموذج Odoo الأصلي يمر عبر صلاحيات Odoo وتحقق نموذج الأعمال؛ لا يُنفّذ أي ترحيل محاسبي آلي من React.
- `saveOdooContact` يقبل الاسم والهاتف والملاحظة فقط، ويمنع أي طلب خارج HTTPS `erp.indexesstore.com/nasqo-mobile/`؛ يتطلب جلسة Odoo صالحة ويطلب تأكيد المستخدم داخل النموذج قبل التنفيذ.
- لا يتم إنشاء سجلات مالية من قبل اختبارات البرمجية؛ اختبارات `tests/odoo-actions.test.mjs` تستخدم Mock `fetch`.
- عملت أزرار الواجهة القديمة التجريبية قبل الربط دون بيانات حقيقية؛ لا تُعامل القيم التجريبية كمجاميع محاسبية.
- Action IDs رقمية، مستخرجة من `ir.actions.act_window` و`ir.model.data` المثبتة على قاعدة Odoo الحالية. قد تتغير عند إعادة تثبيت النظام أو نقل القاعدة؛ يجب تحديث القائمة عند الترحيل.
- الروابط `/odoo/action-<id>` أظهرت تحويلًا إلى تسجيل الدخول عند الوصول المجهول؛ سلوكها بعد تسجيل دخول مستخدم محدود الصلاحيات لم يُختبر بمتصفح مُصادَق عليه.
- شاشة الفاتورة في التصميم لا تحتوي على جدول بنود ضريبية كافٍ؛ لذلك يتم إكمال الإنشاء في Odoo، ولا تُنقل المدخلات الجزئية تلقائيًا.
- قوائم الفواتير وجهات الاتصال الحالية تعرض بحد أقصى 100 سجل لكل نموذج ولا ينبغي استخدامها كإحصائيات شاملة.

## النشر والتحقق المطلوب

1. اختبار `npm run check:runtime`، `npm run build`، `npm run build:erp`، `npm run test:sites`، `npm run test:erp` و`node --test tests/odoo-actions.test.mjs`.
2. الاختبار بحساب Odoo ذي صلاحيات محدودة للقراءة والإضافة والتعديل ورفض الوصول لسجلات الشركات الأخرى.
3. فتح إجراء من Odoo والتأكد من الوصول إلى النموذج المطلوب، وتجربة إنشاء جهة اتصال تجريبية **بعد موافقة مالك قاعدة البيانات فقط**.
4. عدم دمج PR #1 أو اعتبار جميع الوحدات مكتملة دون تلك الاختبارات.
